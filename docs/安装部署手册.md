# Spug-NetMon 安装部署手册

## 1. 项目概述

Spug-NetMon 是在开源运维平台 Spug v3 基础上扩展的网络监控与IP地址管理一体化平台，包含以下核心功能模块：

| 模块 | 说明 |
|------|------|
| 主机管理 | 主机资产录入、分组、SSH密钥验证、扩展信息自动同步 |
| 网络监控 (NetMon) | 设备自动发现、SNMP监控、状态巡检、拓扑可视化 |
| IP地址管理 (IPAM) | 网段管理、地址分配/回收、子网扫描、未授权设备检测与隔离 |
| 监控中心 | 自定义脚本监控、告警规则、通知渠道 |
| 任务调度 | 定时任务、批量执行 |
| 应用发布 | 多环境发布流程 |
| 配置管理 | 配置中心、环境变量 |
| 告警通知 | 多渠道告警推送 |

### 技术栈

| 层级 | 技术 |
|------|------|
| 前端 | React 16 + Ant Design 4 + MobX + react-app-rewired |
| 后端 | Python 3.6 + Django 2.2 + Channels (WebSocket) + Gunicorn + Daphne |
| 数据库 | MariaDB 10.8 (UTF8MB4) |
| 缓存/消息 | Redis 3.2 |
| Web服务器 | Nginx 1.20 |
| 进程管理 | Supervisor |
| 容器化 | Docker + Docker Compose |
| 网络协议 | SNMP (pysnmp)、SSH (paramiko) |

### 内部服务架构

容器内通过 Supervisor 管理以下8个进程：

| 进程 | 端口 | 说明 |
|------|------|------|
| spug-api | 9001 (内部) | REST API 服务 (Gunicorn) |
| spug-ws | 9002 (内部) | WebSocket 服务 (Daphne) |
| spug-worker | - | 异步任务执行器 |
| spug-scheduler | - | 定时任务调度器 |
| spug-monitor | - | 监控检测执行器 |
| spug-netmon | - | 网络设备监控后台 |
| spug-ipam | - | IPAM后台扫描/隔离任务 |
| nginx | 80 | 反向代理 + 静态资源 |
| redis | 6379 (内部) | 缓存与Channel层 |

## 3. Docker 一键部署（推荐）

### 3.1 安装 Docker

**CentOS 7：**

```bash
# 安装依赖
yum install -y yum-utils

# 添加Docker源
yum-config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo

# 安装Docker
yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# 启动并设置开机自启
systemctl enable --now docker
```

**Ubuntu / Debian：**

```bash
apt-get update
apt-get install -y ca-certificates curl gnupg

# 添加Docker GPG密钥和源
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" > /etc/apt/sources.list.d/docker.list

apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

systemctl enable --now docker
```

将项目上传到服务器 `/opt/spug-deploy` 目录：

mkdir -p /opt/spug-deploy

### 3.3 构建应用镜像

```bash
cd /opt/spug-deploy/docker

# 将源码复制到构建上下文
cp -r ../spug_api ./spug_api
cp -r ../spug_web ./spug_web
chmod +x entrypoint.sh

# 构建镜像（约5-10分钟）
docker build -t spug-netmon:latest .

# 清理构建临时文件
rm -rf ./spug_api ./spug_web
```

**Dockerfile 构建过程说明：**

1. 基于 `centos:7.9.2009`，配置阿里云YUM源
2. 安装系统依赖：nginx、redis、mariadb-devel、python36、nodejs 16、supervisor 等
3. 安装Python依赖：Django 2.2、paramiko、pysnmp、channels 等
4. 复制后端代码到 `/opt/spug_src/spug_api`
5. 复制前端代码到 `/opt/spug_src/spug_web`，执行 `npm install && build`
6. 复制配置文件（nginx、supervisor、redis、entrypoint）
7. 暴露80端口，设置入口脚本

### 3.4 启动服务

```bash
cd /opt/spug-deploy/docker

# 启动所有服务
docker compose up -d

# 查看容器状态
docker ps
```

预期输出：

```
NAMES     STATUS                    PORTS
spug      Up ...                    0.0.0.0:80->80/tcp
spug-db   Up ... (healthy)          0.0.0.0:3306->3306/tcp
```

### 3.5 初始化系统

```bash
# 初始化数据库表结构
docker exec spug python3 /data/spug/spug_api/manage.py updatedb

# 创建管理员账户（用户名: admin，密码: 自定义）
docker exec spug python3 /data/spug/spug_api/manage.py user add -u admin -p <你的密码> -n 管理员 -s
```

### 3.6 访问系统

浏览器打开 `http://<服务器IP>` 即可访问，使用上面创建的管理员账户登录。

## 4. 配置说明

### 4.1 Docker Compose 配置详解

文件路径：`docs/docker/docker-compose.yml`

```yaml
version: "3.3"
services:
  db:
    image: mariadb:10.8
    container_name: spug-db
    restart: always
    command: >
      --character-set-server=utf8mb4
      --collation-server=utf8mb4_unicode_ci
      --innodb-buffer-pool-size=256M
      --innodb-log-file-size=64M
      --innodb-flush-method=O_DIRECT
    volumes:
      - /data/spug/mysql:/var/lib/mysql    # 数据库持久化存储
    ports:
      - "3306:3306"                         # 局域网远程访问数据库
    environment:
      - MYSQL_DATABASE=spug                 # 数据库名
      - MYSQL_USER=spug                     # 普通用户
      - MYSQL_PASSWORD=spug.cc              # 普通用户密码
      - MYSQL_ROOT_PASSWORD=spug.cc         # Root密码
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-pspug.cc"]
      interval: 10s
      timeout: 5s
      retries: 5

  spug:
    image: spug-netmon:latest
    container_name: spug
    privileged: true
    restart: always
    volumes:
      - /data/spug/service:/data/spug       # 应用数据持久化
      - /data/spug/repos:/data/repos         # 代码仓库存储
    ports:
      - "80:80"                              # Web界面端口
    environment:
      - MYSQL_DATABASE=spug
      - MYSQL_USER=spug
      - MYSQL_PASSWORD=spug.cc
      - MYSQL_HOST=db                        # 容器内使用服务名连接
      - MYSQL_PORT=3306
      - REDIS_PASSWORD=Redis2024Secure
    depends_on:
      db:
        condition: service_healthy
```

### 4.2 数据卷说明

| 宿主机路径 | 容器路径 | 说明 |
|-----------|---------|------|
| `/data/spug/mysql` | `/var/lib/mysql` | MariaDB数据文件 |
| `/data/spug/service` | `/data/spug` | 应用代码、配置、日志 |
| `/data/spug/repos` | `/data/repos` | Git仓库存储 |

### 4.3 数据库远程访问配置

默认已开放3306端口映射，局域网内其他主机可通过以下方式连接：

| 参数 | 值 |
|------|-----|
| 主机 | 192.168.10.203（部署服务器IP） |
| 端口 | 3306 |
| 数据库 | spug |
| 用户名 | spug / root |
| 密码 | spug.cc |

**安全建议：** 生产环境请修改默认密码，可通过修改 `docker-compose.yml` 中的 `MYSQL_PASSWORD` 和 `MYSQL_ROOT_PASSWORD` 实现。

### 4.4 Nginx 配置

文件路径：`docs/docker/nginx.conf`

- 监听80端口
- `/api/` 路径反向代理到 Gunicorn (127.0.0.1:9001)
- `/api/ws/` 路径反向代理到 Daphne WebSocket (127.0.0.1:9002)
- 静态资源从 `/data/spug/spug_web/build` 提供
- 启用Gzip压缩

### 4.5 Supervisor 配置

文件路径：`docs/docker/spug.ini`

管理8个进程：nginx、redis、spug-api、spug-ws、spug-worker、spug-monitor、spug-scheduler、spug-netmon、spug-ipam

### 4.6 容器入口脚本

文件路径：`docs/docker/entrypoint.sh`

首次启动时：
1. 将源码从 `/opt/spug_src/` 复制到 `/data/spug/`（仅首次）
2. 生成 `overrides.py` 配置文件（含SECRET_KEY、数据库连接、Redis连接、Channel层配置）
3. 启动 supervisord

### 5.1 服务管理

```bash
# 查看服务状态
docker ps

# 查看特定服务日志
docker exec spug tail -f /data/spug/spug_api/logs/api.log

cd /opt/spug-deploy/docker && docker compose up -d
```

### 5.2 数据库备份

```bash
# 手动备份
docker exec spug-db mysqldump -uroot -pspug.cc --all-databases --single-transaction > /data/spug_backup_$(date +%Y%m%d).sql

# 恢复备份
docker exec -i spug-db mysql -uroot -pspug.cc < /data/spug_backup_20260804.sql
```

**定时备份（crontab）：**

```bash
# 每天凌晨2点自动备份
echo "0 2 * * * docker exec spug-db mysqldump -uroot -pspug.cc --all-databases --single-transaction | gzip > /data/spug_backup_\$(date +\%Y\%m\%d).sql.gz" | crontab -
```

### 5.3 更新部署

当代码有更新时：

```bash
cd /opt/spug-deploy/docker

# 1. 更新源码文件
cp -r ../spug_api ./spug_api
cp -r ../spug_web ./spug_web
chmod +x entrypoint.sh

# 2. 重新构建镜像
docker build -t spug-netmon:latest .

# 3. 清理构建临时文件
rm -rf ./spug_api ./spug_web

# 4. 重启服务（使用新镜像）
docker compose down
docker compose up -d

# 5. 执行数据库迁移（如有）
docker exec spug python3 /data/spug/spug_api/manage.py updatedb
```

### 5.4 仅更新后端代码（无需重新构建镜像）

当只修改了Python后端代码时，可以快速更新：

```bash
# 1. 将修改的文件复制到容器
docker cp /opt/spug-deploy/spug_api/apps/host/views.py spug:/data/spug/spug_api/apps/host/views.py
docker cp /opt/spug-deploy/spug_api/apps/host/utils.py spug:/data/spug/spug_api/apps/host/utils.py

# 2. 重启容器使代码生效
docker restart spug
```

### 5.5 仅更新前端代码

当只修改了前端React代码时：

```bash
# 1. 将修改的源码复制到容器内的构建目录
docker cp /opt/spug-deploy/spug_web/src/pages/host/store.js spug:/opt/spug_src/spug_web/src/pages/host/store.js

# 2. 在容器内重新构建前端

```

## 7. 常见问题排查

### 7.1 容器启动失败

```bash
# 查看容器日志
docker logs spug
docker logs spug-db

# 检查端口占用
ss -tlnp | grep -E '80|3306'

# 检查磁盘空间
df -h
```

### 7.2 数据库连接失败

```bash
# 检查数据库容器状态
docker exec spug-db mysqladmin ping -h localhost -u root -pspug.cc

# 检查数据库用户权限
docker exec spug-db mysql -uroot -pspug.cc -e "SELECT user, host FROM mysql.user;"

# 重新授权
docker exec spug-db mysql -uroot -pspug.cc -e "GRANT ALL PRIVILEGES ON spug.* TO 'spug'@'%' IDENTIFIED BY 'spug.cc'; FLUSH PRIVILEGES;"
```

### 7.3 主机验证失败

- **E00错误**：目标主机不支持密码认证，检查 `/etc/ssh/sshd_config` 中 `PasswordAuthentication yes`
- **E01错误**：目标主机不支持密钥认证，检查 `PubkeyAuthentication yes`
- **E02错误**：密码认证成功但密钥认证失败，通常是目标主机OpenSSH版本较新禁用了ssh-rsa算法，系统会自动重新生成密钥对并重试

### 7.4 主机扩展信息显示为空

非标准Linux设备（如交换机、路由器）可能无法获取CPU、内存等信息，系统会使用默认值（0核、0GB），不影响正常使用。

### 7.5 前端构建失败

```bash
# 检查Node.js版本（需要16.x）
docker exec spug node -v

# 清除缓存重新构建
docker exec spug bash -c 'cd /opt/spug_src/spug_web && rm -rf node_modules && npm install --legacy-peer-deps && npx react-app-rewired build && cp -r build/* /data/spug/spug_web/build/'
```

## 8. 安全加固建议

1. **修改默认密码**：修改 `docker-compose.yml` 中的数据库密码和Redis密码
2. **限制3306端口访问**：如不需要远程数据库访问，移除 `ports: "3306:3306"` 配置
3. **启用HTTPS**：在Nginx配置中添加SSL证书，或在前端部署反向代理
4. **定期备份**：配置crontab定时备份数据库
5. **更新系统**：定期更新Docker镜像和系统安全补丁
6. **限制SSH访问**：配置防火墙仅允许管理网段访问服务器SSH
